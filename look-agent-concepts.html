Look 里的 Agent 是什么

Look 是基于 pi SDK 的多 agent 桌面应用。 这里的 "agent" 有 两层含义：模板（agent role）和 实例（agent session）。 下面这张图把 Look agent 跟 pi SDK 之间的关系、生命周期、持久化都串起来。

Look 管 "和用户怎么聊 + 多 agent 怎么玩"； pi 管 "和模型怎么聊 + 消息怎么存"。两个层是正交的。

028 个 Role 模板（静态）

Chat 通用助手

read, bash, write, edit, grep, find, ls

默认 Sonnet 4，medium thinking。最常用的 "聊天" 入口。

Orchestrator

+ spawn / send / ask / wait / list_agents

协调者，能创建子 agent 并分配任务（多 agent 编排的入口）。

Coder

read, bash, write, edit, grep, find, ls

写代码、debug。Sonnet 4 / medium。

Reviewer

read, grep, find, ls（只读）

只读审代码，Haiku / off thinking（轻量）。

Crawler / Cleaner / Analyst / Reporter

数据处理管线

四个数据类角色：Crawler 抓 → Cleaner 洗 → Analyst 分析 → Reporter 写报告。

Custom

read, bash, write, edit

用户自定义的 agent，落不进上面任何角色时的兜底。

03AgentInfo 实例字段（运行时）

id
8 字符 UUID，创建时生成
name
用户起的名字（"聊天助手" / "SQL Bot"）
role
引用上面的 8 个 role 模板之一
model
当前用的具体模型（启动时 resolve model 链决定）
thinkingLevel
off / minimal / low / medium / high / xhigh
status
idle | thinking | working | error | destroyed
messageCount
本地缓存，render 端快查用
usage
累计 token + cost 快照
fallbackModels
主模型挂了回退的备选链
permissionMode
ask / plan / allow（per-agent 权限档）

07Multi-agent 通信（Orchestrator 专属）

sequenceDiagram participant U as 用户 participant Orc as Orchestrator agent participant Sub1 as Coder agent participant Sub2 as Reviewer agent U->>Orc: "分析这个 repo" Orc->>Orc: LLM 决定调 spawn_agent("Coder") Orc->>Sub1: spawn_agent(role=coder, task="...") Sub1-->>Orc: agentId Orc->>Orc: LLM 决定调 spawn_agent("Reviewer") Orc->>Sub2: spawn_agent(role=reviewer) Sub2-->>Orc: agentId Orc->>Sub1: send_to_agent(agentId, "补充要求") Orc->>Sub2: ask_agent(agentId, "检查 X") Sub2-->>Orc: 回答 Orc->>Sub1: wait_for_agent(agentId) Sub1-->>Orc: done Orc->>U: 汇总报告

5 个工具：spawn_agent / send_to_agent / ask_agent / wait_for_agent / list_agents。 只有 orchestrator role 能用——其他 agent 没有这些工具。

08关键文件索引

agent-manager.ts 核心 — Map<id, ManagedAgent> ＋ pi session 包装
roles.ts 8 个 agent role 模板（默认 model/thinking/工具）
tools/orchestration.ts 5 个多 agent 通信工具（orchestrator 专用）
permissions/permission-ask.ts Async ask 服务 + extensionFactory tool_call 拦截
permissions/permission-gate.ts 三层规则：global deny / role-based / path-protected
user-settings.ts 用户偏好持久化（language / thinking level / auto-collapse）
shared/look-storage.ts ~/.look/ 路径管理 + ensureLookDir()
shared/message-convert.ts pi AgentMessage → UI AgentMessage 转换
shared/types.ts AgentInfo / AgentMessage / MainToRendererEvent 全部类型
ipc-handlers.ts 主 ↔ 渲染 事件路由，permission:ask / respond 双向

09Look 做的 vs pi 做的

Look 独有

role 模板、permission 拦截、orchestration 工具、permissionMode per-agent、UI 状态、跨进程 IPC、Ask/Plan/Allow 切换

pi 负责

session 生命周期、消息流 .jsonl、retry、compaction、tool 执行、provider auth、model registry、订阅事件流
